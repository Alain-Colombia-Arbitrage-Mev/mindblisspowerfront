# Reduccion de llamadas API del cliente

Rama: `feature/api-cache-20261023`. Base: `13831dd`.
Cambios locales, sin push ni despliegue.

## Alcance

- El shell comparte su lectura de sesion con Perfil y el resumen mediante
  React Context. No hay un segundo GET de sesion por cada componente hijo.
- El contexto vive solo durante el montaje del dashboard; no se persiste
  en localStorage, cookies ni una cache global de servidor. Es informacion
  de presentacion, nunca una decision de autorizacion.
- El cambio de nombre confirmado por el POST de perfil sigue actualizando
  el contexto mediante el evento existente `vp:profile-updated`.
- Solo el catalogo no personal de rangos se conserva 60 segundos en memoria
  del navegador. Peticiones concurrentes comparten una sola promesa.
- Cada consumidor recibe su propia copia. Errores y respuestas invalidas no
  se guardan. Hay refresco forzado e invalidacion explicita, protegidos
  contra respuestas antiguas que lleguen despues de la invalidacion.
- SSR evita esta cache de navegador. La cache de catalogo del servidor
  existente, de cinco minutos, no se modifica; los 60 segundos adicionales
  no garantizan que un cambio de catalogo sea visible en ese plazo.
- La posicion y rango efectivo del miembro se consultan en cada visita.
  No se agrego cache a saldos, ventas, comisiones, pagos, blacklist,
  posiciones, verificaciones de acceso ni OTP. No se modifico Go ni SQL.

## Medicion reproducible local

Chrome con Playwright, componentes reales y HTTP sintetico de solo lectura.
Los conteos son peticiones GET del navegador, no carga real de produccion.

| Escenario | Antes | Despues | Reduccion |
| --- | ---: | ---: | ---: |
| Apertura de Perfil, todas sus API | 4 | 3 | 25% |
| GET de sesion durante esa apertura | 2 | 1 | 50% |
| Catalogo durante cinco visitas a Rangos dentro del TTL | 5 | 1 | 80% |
| Posicion durante esas cinco visitas | 5 | 5 | Sin cache |

La fixture local esta fuera de este repositorio:
`D:/vicionpower/reportes/cache-api-20261023/`.
Ejecutar `node count.mjs --verify` desde esa carpeta, con Bun en PATH y
`CODEX_NODE_MODULES` apuntando al directorio que contiene Playwright.
Necesita ambos repositorios hermanos y sus builds. No necesita credenciales
de produccion. Los tests unitarios si forman parte de esta rama.

## Validacion y limites

- `npm test`: 117 pruebas correctas.
- `npm run build`: correcto. No equivale a un typecheck global sin deuda.
- `npm run lint`: conserva 269 errores de imports sin usar en archivos
  ajenos a este cambio. No se ejecutaron correcciones masivas.
- Tests del recurso: concurrencia, TTL desde finalizacion, expiracion,
  errores, copias aisladas, refresco e invalidacion con cargas pendientes.
- Tests del catalogo: 403/500, formato invalido, descarte de campos
  personales adicionales y ausencia de cache compartida durante SSR.
- Regresion Playwright: cinco tamanos de pantalla, menus, carga, error,
  reintento y saldo cero, sin excepciones JS ni desbordamiento horizontal.
- Next local de produccion: login 200 y API privada sin sesion 401.

No es una certificacion de capacidad para 1.100 usuarios simultaneos.
Queda pendiente la prueba autenticada en staging y una prueba de carga con
distribucion real de operaciones. La deuda global previa de lint/TypeScript
no se corrige ni se oculta en esta rama.
